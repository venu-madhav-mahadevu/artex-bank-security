Is ARTEX illegal to use?
No — the tool itself is legal and open-source. Using it against systems you don't own or aren't authorized to test is illegal. Run it only on your own or approved systems, in an isolated lower environment, with security-team sign-off.
Does ARTEX use new zero-day exploits?
No. In the reported incidents it used no zero-days. It chained known, preventable weaknesses — weak credentials, missing MFA, SQL injection, SSRF, exposed admin pages, leaked secrets — at machine speed. Speed, scale and a lower skill floor are what changed.
If I run the checker and it's clean, am I safe?
Not necessarily. A clean scan means no obvious pattern matched. Logic flaws (IDOR, payment limits, OAuth scopes, liveness, detection) can't be found by grep and need manual testing. Treat a pass as 'nothing obvious', not 'secure'.
What should we fix first?
Secrets and anything reachable without a login. Then, in order: MFA + rate limiting, kill default creds / exposed admin, parameterize queries, payment-API guards, vendor-app review, SSRF/IMDSv2/XXE, server-side liveness, machine-speed detection.
Can ARTEX break into our systems on its own?
It automates the steps a skilled attacker would take — recon, probing, chaining — with little human help once pointed at a target. But it exploits existing weaknesses; it doesn't invent access where good hygiene removes the gaps.
Do we need to rotate our Firebase/Google web API key if it's in the repo?
A Firebase web API key is public by design — it identifies the project, it isn't a password. The real fix is to restrict it (HTTP-referrer + API restrictions) and lock your security rules, not just rotate it.
Is it safe to paste our code into a website to check it?
No — don't paste source into any website, even one that says it runs in your browser. Use the local scanner (check-code.sh) and tools like gitleaks/semgrep on your own machine, so code never leaves it.
How is this different from a normal vulnerability scanner?
Traditional scanners flag issues from a checklist. ARTEX-style agents reason: they plan, try things, adapt to what they find, and chain several small weaknesses into one compromise — autonomously and fast.
What does ‘identity is the new perimeter’ mean for us?
Credentials, tokens and app permissions are the main targets. MFA on humans isn't enough if a vendor OAuth app can sign in as itself with broad scopes. Watch app credentials and service-principal sign-ins, not just user logins.
We're a small team — where do we even start?
Run the self-assessment for a prioritized list, fix the red items, adopt the local checks in CI, and build new services from the secure baseline in the repo. Small, steady hygiene beats most of this.
