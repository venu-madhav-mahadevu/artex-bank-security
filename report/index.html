Defensive Security Brief

ARTEX: the issues
and how to stop them

How the AI-agent penetration framework ARTEX was used against banks and major services in Oct–Nov 2026 — and the fixes that neutralise each attack at the code and control level.

ARTEX chained known, preventable weaknesses — weak credentials, no rate limit, no MFA, SQL injection, missing API auth, exposed admin pages, leaked secrets, over-privileged OAuth apps — at machine speed, in parallel, with little human supervision. How it operates

A planner and worker loop, running real tools

An operator sets a plain-language goal; agents break it into steps and execute until the goal is met, a human intervenes, or the budget runs out. Understanding the loop shows where defenses must hold.

01 · RECON

Map the surface

Subdomain & port enumeration, directory fuzzing, asset-graph building via ScopeSentry.

02 · ACCESS

Get a foothold

Password spray, default creds, SQLi, auth bypass, leaked API keys from code and repos.

03 · EXPLOIT

Chain weaknesses

IDOR, SSRF to cloud metadata, file upload to web shell, RCE — self-correcting on failure.

04 · EXFIL

Take & persist

Read databases, harvest secrets, add OAuth credentials, exfiltrate PII over HTTPS.

The issues & the fixes

Every weakness, mapped to a defense

Each card: what the weakness is, why it works for an autonomous agent, the code-level fix, and the control that prevents recurrence.

01

No rate limit · no MFA

Critical · credential attacks
Why it works

Login, search and lookup endpoints with no throttle let an agent spray 150k+ attempts and stuff leaked passwords at machine speed.

Fix

Rate-limit per account + IP + device; progressive lockout tuned for bursts, not human pace. Phishing-resistant MFA (passkeys/WebAuthn) everywhere, with step-up on sensitive actions. Screen against breached-password lists; block legacy auth.

Prevent

Alert on login bursts, impossible travel and abnormal records-per-session, especially on partner/employee portals.

02

SQL injection

Critical · data access
Why it works

String-concatenated queries let an agent dump credentials and read sensitive tables; error-based SQLi gives it feedback to iterate.

Fix

Parameterised queries / prepared statements everywhere; never concatenate input into SQL. Validate and allow-list input. Run the app on a least-privilege database account.

Prevent

SAST/DAST in CI, a WAF in front, and generic error messages so no stack trace leaks to the attacker.

03

Authentication bypass

Critical · identity
Why it works

Unsigned/forged SAML assertions and trusted client headers (e.g. an isCliRequest bypass) let an agent walk past login entirely.

Fix

Validate the SAML signature before trusting any assertion; reject unsigned assertions and pin the IdP certificate. Never trust client-supplied headers for auth decisions; centralise authentication.

Prevent

Negative tests with tampered tokens and assertions in CI; fail closed on any validation error.

04

IDOR / broken object authz

Critical · authorization
Why it works

APIs that check login but not ownership let an agent enumerate other users' records by changing an ID — ideal for automated harvesting.

Fix

Enforce object-level authorization on every request: confirm the caller may access that specific object. Deny by default; use unguessable identifiers; centralise the check, don't scatter it.

Prevent

Per-endpoint authorization tests; monitor for sequential-ID access patterns.

05

SSRF & XXE → cloud metadata

Critical · cloud takeover
Why it works

URL-fetch and XML parsers that reach internal addresses let an agent pull cloud instance credentials from the metadata service.

Fix

Allow-list outbound destinations; block link-local and metadata IP ranges. Require IMDSv2. Disable external entities in every XML parser.

Prevent

Egress filtering and network segmentation so a fetch can't reach the control plane.

06

Unrestricted file upload

High · remote code exec
Why it works

Anonymous uploads with no validation let an agent drop a web shell and run commands on the server.

Fix

Validate type and size, store files outside the web root with random names, disable execution in upload paths, scan on receipt, and serve downloads from a separate domain.

Prevent

Content-type and magic-byte checks; no user-controlled paths; monitor new executable files in served directories.

07

Secrets in code, JS & repos

Critical · the fastest way in
Why it works

API keys in client JavaScript, source maps, .env files and public repos are harvested in minutes — one case went from a GitHub search to key-vault exfiltration in 5 minutes.

Fix

Move secrets to a vault; issue short-lived, rotatable credentials. Strip secrets from client bundles and source maps. Add CI secret-scanning and pre-commit hooks that block pushes containing keys.

Prevent

Rotate immediately on any exposure; monitor public repos and paste sites for your key patterns.

08

Exposed admin / debug & weak sessions

High · surface exposure
Why it works

Forgotten admin pages, live debug routes, uninitialised installs and guessable session tokens give an agent a quiet way in.

Fix

Remove debug routes in production; gate admin behind auth + MFA + IP allow-list. Harden sessions: strong random tokens, short expiry, rotate on login, HttpOnly/Secure/SameSite cookies.

Prevent

Keep an inventory of every internet-facing surface, including peripheral partner, employee and mobile-backend apps; close uninitialised installs.

09

Payment / disbursement API abuse

Critical · fund transfer
Why it works

Disbursal APIs invoked from whitelisted infrastructure can skip loan-creation, KYC, sanction, beneficiary, balance and limit checks when those sit only in the application layer.

Fix

Enforce a server-side state machine: no disbursal until each prior check passes. Add maker-checker (dual approval) for fund movement. Don't treat a whitelisted source IP as authorization.

Prevent

Detect small "test" transactions and abnormal disbursal patterns; re-check scope after any incomplete remediation.

10

Over-privileged vendor OAuth apps

Critical · supply chain
Why it works

Trusted multi-tenant apps with broad consent let an agent authenticate as the app — no user sign-in, no MFA prompt — and add credentials for lasting persistence.

Fix

Grant third-party and OAuth apps least privilege; review and scope existing consents. Connect partners through scoped APIs, never shared passwords. Alert when app credentials are added or changed.

Prevent

Monitor service-principal sign-ins and conditional access for app identities; revoke dormant grants.

11

Deepfake liveness bypass

High · identity verification
Why it works

Agents try real-time deepfake video and forged ID photos, and reverse-engineer a vendor's liveness event stream to spoof the check from the client side.

Fix

Reach the liveness verdict server-side — never trust the client's event stream. Use randomised challenges, device and metadata integrity checks, and combine passive with active liveness.

Prevent

Flag synthetic camera metadata and parallel verification sessions. (In the one primary record, every attempt was rejected — keep it that way.)

12

No machine-speed detection

High · the meta-issue
Why it works

Controls tuned to human pace miss an agent that probes permissions, enumerates and pivots in seconds, inheriting sessions a human already authenticated.

Fix

Add behavioural detection for identity-velocity anomalies, API bursts, permission-probing and dry-run capability checks. Distinguish who decided from who logged in; require explicit human confirmation for irreversible actions.

Prevent

Baseline normal volume per identity and alert on deviation; put internal and treasury apps behind Zero Trust access.

Where to start

Fix-first priority order

Not everything at once. This sequence closes the paths ARTEX used most, fastest.

▶ Do this week
  • Rotate & vault exposed secrets; strip keys from client JS
  • Rate-limit + lockout on all login/lookup endpoints
  • Remove debug routes; lock admin behind MFA + allow-list
▶ Do this month
  • Parameterise all queries; fix SAML & auth-bypass gaps
  • Object-level authz on every API (IDOR)
  • SSRF allow-listing + IMDSv2; safe file-upload handling
▶ Do this quarter
  • Payment-API state machine + maker-checker
  • Least-privilege vendor OAuth; service-principal monitoring
  • Server-side liveness; machine-speed behavioural detection
Catch it in motion

Detection signals for an autonomous agent

  • Login bursts measured in seconds, not minutes; mass lockouts
  • Sequential or enumerating access to records / object IDs
  • Sub-second permission and capability probing (dry-run calls)
  • New app or OAuth credentials added to existing identities
  • Service-principal sign-ins from new IPs across many tenants
  • Outbound traffic to rotating webhook / paste endpoints
  • Abnormal records-per-session on partner and employee portals
  • Small "test" transactions ahead of a larger disbursal
