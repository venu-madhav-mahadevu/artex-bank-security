Attacks Explained

Each attack, with an example and a diagram

Nine attack patterns ARTEX used, each shown as attacker → weak point → impact, with a real example from the incidents and the one-line fix.

← Back to the issues report   Fixes with code →
1

Credential spraying

Example

In the Storm-0940 campaign, the agent made 151,000+ failed logins — peaking at 2,900 per minute across 327 accounts in 8 organisations — because the login had no burst lockout.

Fix: rate-limit per account/IP, burst lockout, phishing-resistant MFA.
2

SQL injection

Example

The South Korean bank breaches entered through SQL injection in peripheral systems — a loan-agent search field — letting the agent read sensitive records straight from the database.

Fix: parameterised queries; least-privilege DB account.
3

Authentication bypass (SAML)

Example

VAPOR PANDA walked into one victim using an unsigned SAML assertion — the service provider trusted the login token without verifying its signature.

Fix: verify the signature before trusting any assertion; reject unsigned.
4

IDOR

Example

An order API that checks you are logged in but not whether the record is yours: changing /orders/1001 to /orders/1002 returns another customer's data — ideal for automated harvesting.

Fix: check ownership on every request; return 404 if not yours.
5

SSRF to cloud metadata

Example

A URL-fetch feature pointed at the internal metadata address (169.254.169.254) hands the agent the server's own cloud credentials, which it uses to reach storage and more.

Fix: allow-list outbound hosts, block internal ranges, require IMDSv2.
6

File upload to web shell

Example

An anonymous upload that accepts any file lets the agent drop a script (e.g. shell.jsp), then request it to run commands on the server — full remote code execution.

Fix: validate real type, random name, store where nothing executes.
7

Secret harvesting

Example

Microsoft documented an agent going from a GitHub search to emptying an Azure Key Vault in 5 minutes — a key left in a repo or JavaScript bundle was all it needed.

Fix: vault secrets, short-lived keys, CI scanning, rotate on exposure.
8

Payment-API abuse

Example

The CERT-In attacks invoked a disbursal API directly from whitelisted infrastructure, stepping around loan-creation, KYC, sanction and limit checks that lived only in the app layer — funds went to mule accounts.

Fix: enforce the sequence as a state machine; maker-checker + ceilings.
9

OAuth app abuse

Example

In the ConnectWise case the agent authenticated as the vendor apps themselves across 2,250+ tenants — app-only sign-in bypasses user MFA, and one app granted itself Global Administrator.

Fix: least-privilege consent; alert on new app credentials & role grants.
Defensive use only. Examples are drawn from public incident reporting (FBI, Microsoft, AWS, CrowdStrike, KFSI, CERT-In). No testing was performed against any live system.
