How to check your code — locally, nothing uploaded

⚠️
Never paste source code into this site or any website, even one that says it runs only in your browser. Run the commands below on your own machine — your code stays local and is never sent anywhere.
1Get the scanner (one time)

Clone the repo, or open the script on GitHub and copy it into a file called check-code.sh if your laptop blocks cloning.

shell
git clone https://github.com/venu-madhav-mahadevu/artex-bank-security.git
2Run it on your project

Point it at the folder you want to check. It scans every file locally and prints the findings in your own terminal — nothing leaves the machine.

shell
cd /path/to/your/project
bash check-code.sh .
3Add the standard scanners (also 100% local)

These go deeper than grep — secrets hidden in git history, code bugs, and vulnerable dependencies.

shell
gitleaks detect --source .      # secrets (incl. git history)
semgrep --config auto .         # code vulnerabilities
npm audit                       # dependencies (Node)
pip-audit                       # dependencies (Python)
4Read the results & act

For each weakness below you'll find the exact search command and the safe-vs-vulnerable code. Fix order: secrets and anything reachable without a login first, then logic bugs. The 5 manual-only checks (IDOR, payments, OAuth scopes, liveness, detection) can't be grepped — test those by hand.

A1

No rate limit / no MFA

Manual test needed
Search your code
shell
rg -n "post\(.*(login|signin|authenticate)" .   # is there a limiter + MFA?
Vulnerable
app.post('/login', loginHandler)   // no throttle, no MFA
Safe
app.post('/login', rateLimiter, loginHandler)
// lock out after a burst; require phishing-resistant MFA;
// step-up before payments / beneficiary / limit changes
Mostly config — also test it: script rapid logins and confirm lockout + MFA prompt.
A2

SQL injection

Scanner catches it
Search your code
shell
rg -n "execute\(.*\+|query\(.*\+|\"SELECT.*\" *\+" .
Vulnerable
db.query("SELECT * FROM users WHERE id = " + id)
Safe
db.query("SELECT * FROM users WHERE id = ?", [id])   // bound parameter
Also run sqlmap against a test endpoint — it should find nothing.
A3

Authentication / SAML bypass

Scan + manual
Search your code
shell
rg -n "SAMLResponse|verify.*[Ss]ignature|headers\[.*(role|user|admin)" .
Vulnerable
const user = parseAssertion(xml);           // no signature check
if (req.headers['x-role'] === 'admin') {...}  // trusts a client header
Safe
if (!verifySignature(xml, idpCert)) reject();   // validate first, reject unsigned
const role = req.session.role;                   // from server session, never headers
Test with a tampered / unsigned assertion — it must be rejected.
A4

IDOR (broken object authz)

Manual test needed
Search your code
shell
rg -n "findById\(req|findOne\(.*req\.params|WHERE id =" .   # then read each by eye
Vulnerable
const o = await Order.findById(req.params.id);
res.json(o);                     // any id works
Safe
const o = await Order.findById(req.params.id);
if (!o || o.userId !== req.user.id) return res.status(404).end();
No scanner finds this. Test: log in as user A, request user B's object id — you should get 404.
A5

SSRF & XXE → cloud metadata

Scanner catches it
Search your code
shell
rg -n "fetch\(|requests\.(get|post)|urlopen\(|DocumentBuilderFactory|etree\.parse" .
Vulnerable
const r = await fetch(req.query.url);          // SSRF
new DocumentBuilder().parse(xml);              // XXE (DTD enabled)
Safe
const h = new URL(req.query.url).host;
if (!ALLOWED.has(h)) throw new Error('blocked');  // allow-list; block 169.254/internal; IMDSv2
f.setFeature('http://apache.org/xml/features/disallow-doctype-decl', true);  // kill XXE
Try pointing a fetch at 169.254.169.254 on a test host — it must be blocked.
A6

File upload to web shell

Scan + manual
Search your code
shell
rg -n "multer|MultipartFile|request\.files|move_uploaded_file|\.mv\(" .
Vulnerable
file.mv('./public/uploads/' + file.name);   // original name, inside web root
Safe
if (!ALLOWED.has(sniffType(buf)) || buf.length > MAX) reject();
save(buf, '/var/uploads/' + uuid());          // random name, outside web root, no execute
Try uploading a .jsp/.php shell to a test instance — it must be rejected or non-executable.
A7

Secrets in code / repos

Scanner catches it
Search your code
shell
rg -ni "(api[_-]?key|secret|password|token)\s*[:=]\s*[\"\x27]" .   # or: gitleaks detect
Vulnerable
const stripeKey = "sk_live_51H...";          // key in code
Safe
const stripeKey = process.env.STRIPE_KEY;    // from vault/env; rotate on exposure; scan CI
Also scan git history and JS bundles — keys hide there too.
A8

Exposed admin/debug & weak sessions

Scanner catches it
Search your code
shell
rg -n "DEBUG\s*=\s*True|/debug|/actuator|secure\s*[:=]\s*false|httpOnly\s*[:=]\s*false" .
Vulnerable
app.get('/debug/env', ...)                    // live in prod
res.cookie('sid', id, { secure:false })       // weak cookie
Safe
// remove debug/actuator routes in prod; gate admin behind MFA + IP allow-list
res.cookie('__Host-sid', id, { httpOnly:true, secure:true, sameSite:'strict' })
Change every default credential; inventory all internet-facing surfaces.
A9

Payment / disbursement API abuse

Manual test needed
Search your code
shell
rg -n "disburse|payout|transfer|withdraw" .   # then review the guard logic
Vulnerable
router.post('/disburse', (req) => gateway.transfer(req.body.amount, req.body.to));
Safe
require(p.state === 'APPROVED' && p.kyc && p.makerId !== actor.id
        && withinCeilings(p));   // server-side state machine + maker-checker + limits
gateway.transfer(p);
Business logic — no scanner finds it. Test: call the disbursal API skipping KYC/limits; it must refuse.
A10

Over-privileged vendor OAuth apps

Config review
Search your code
shell
No code grep — review consented apps & scopes in your identity provider.
Vulnerable
App consented with broad scopes / granted Global Administrator
Safe
Least-privilege scopes only; alert on new app credentials & role grants; monitor service-principal sign-ins
This lives in your IdP (Entra/Okta/Google), not the codebase. Audit consents there.
A11

Deepfake / liveness bypass

Scan + manual
Search your code
shell
rg -n "liveness|livenessPassed|faceMatch|verified\s*[:=]\s*req" .
Vulnerable
if (req.body.livenessPassed) approve();       // trusts the client
Safe
const ok = computeLivenessServerSide(frames); // verdict server-side, never client
if (!ok || virtualCameraDetected) reject();
Test the verification flow: a client-sent 'passed' flag must not be trusted.
A12

No machine-speed detection

Config review
Search your code
shell
No code grep — this is monitoring. Check your SIEM/SOC alerting.
Vulnerable
Daily log review only; no alert on bursts or enumeration
Safe
Real-time alerts on login bursts, sequential enumeration, new app credentials, sub-second permission probing; automate containment
Test it with a detection drill: simulate a burst and confirm an alert fires.
Run locally, on authorized code only. These are pattern searches, not a full scanner. Logic flaws (IDOR, payment sequencing, OAuth scopes, liveness, detection) need manual testing they cannot see. Verify findings on a test environment before changing production.
